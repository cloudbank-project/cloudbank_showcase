# CloudBank Showcase — Documentation Site

This folder contains a [Docusaurus](https://docusaurus.io) site that presents
all the showcase tutorials (markdown guides + Jupyter notebooks) as a browsable
documentation website.

The site is generated **from the tutorial sources** in the repository root —
there is no duplicate content. `npm run sync` regenerates the site content
from the tutorial folders; never edit the generated files by hand.

## Why Docusaurus (instead of MkDocs)

- Mature, actively maintained SSG with first-class markdown support, MDX,
  code highlighting, and a built-in search-ready theme.
- Static rendering of Jupyter notebooks is easy to add (see below) with plain
  Node — no Python/Jupyter dependency is required to build the site.
- Easy GitHub Pages publishing via a standard Actions workflow
  (`.github/workflows/docs.yml`).

## Layout

```
website/
├── docs/                  # site content (authored here: index, about, contributing)
│   └── tutorials/         # GENERATED by `npm run sync` (git-ignored)
├── scripts/sync.mjs       # copies guides + converts .ipynb -> markdown
├── static/                # icons/images
├── sidebars.js            # doc sidebar structure
└── docusaurus.config.js
```

### How tutorials are mapped

Each tutorial folder at the repo root is mapped in `scripts/sync.mjs`
(the `TUTORIALS` array):

| Tutorial | Source folder | Site section |
|----------|---------------|--------------|
| GPU Computing in Oceanography | `gpu_computing_oceanography/` | `tutorials/gpu-oceanography/` |
| Knowledge Graphs for Chemistry | `knowledge_graphs_chemistry/docs/` | `tutorials/knowledge-graphs-chemistry/` |
| Cloud Seismology Analysis | `cloud_analysis_seismology/` | `tutorials/cloud-seismology/` |
| Toy Data Portal for Hydrology | `toy_data_portal_hydrology/` | `tutorials/toy-data-portal/` |

Guides are copied with their original filenames (so relative links and
images keep working) and a small frontmatter block is injected
(`title`, `sidebar_position`). Linking conventions (`<https://...>`
autolinks, `:::note` admonitions, relative `.md`/`.ipynb` links) are
handled by the sync script so the rendered site is clean.

### Notebook rendering

`.ipynb` files are converted to static markdown by the sync script:

- markdown cells → page text
- code cells → highlighted code blocks
- text outputs → text blocks
- PNG outputs → saved next to the page and embedded

The raw notebook is always linked from the rendered page (GitHub).
No Python/Jupyter is needed to build.

## Usage

```bash
cd website
npm install
npm run sync        # (re)generate docs/tutorials from the tutorial sources
npm run start       # development server (http://localhost:3000)
npm run build       # production build -> website/build/
npm run serve       # serve the production build locally
```

`start`, `build` and `serve` run `sync` automatically.

## Deployment

`.github/workflows/docs.yml` builds and deploys the site to GitHub Pages on
every push to `main`. The config uses:

- `url: https://cloudbank-project.github.io`
- `baseUrl: /cloudbank_showcase/`

Adjust both in `docusaurus.config.js` if the site is hosted elsewhere.

## Adding a tutorial

1. Add its guides/notebooks to a new folder at the repo root.
2. Add an entry to `TUTORIALS` in `scripts/sync.mjs` (files + titles).
3. Add a category to `sidebars.js`.
4. Add a row to `docs/index.md` and to the repository `README.md`.
